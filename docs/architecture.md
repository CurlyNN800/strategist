# Архитектура и форматы данных

Это договорённость команды: и инструкции агента, и скрипты читают и пишут файлы
строго в этих форматах. Меняем формат — меняем этот документ, схемы в
`docs/schemas/` и пример в `projects/_example/` в одном коммите.

## 1. Папка задачи

Каждая задача живёт в `projects/<task_id>/`. `task_id` — латиница, цифры и дефис:
`habit-retention`, `esim-launch`.

| Файл | Кто пишет | Что внутри |
| --- | --- | --- |
| `brief.md` | этап 01 | постановка: вопрос, цель, получатель, ограничения, данные |
| `state.json` | `scripts/state.py` | где мы сейчас: этапы, шаги, ожидание человека |
| `log.md` | `scripts/state.py` | хронология: что сделано и на каком основании |
| `cost.csv` | `scripts/cost.py` | расходы по шагам |
| `sources.yaml` | `fetch_source.py`, `extract.py` | реестр источников |
| `sources/` | те же скрипты | локальные копии источников (`S001.md`, `S002.csv`, …) |
| `evidence.jsonl` | этапы 02–07 | реестр утверждений, одна запись на строку |
| `situation.md` | этап 03 | картина ситуации: известно / предполагаем / не знаем |
| `options.md` | этап 04 | варианты с возражениями |
| `decision.md` | этап 05 | выбор человека и его основания |
| `product-strategy.md` | этап 06 | продуктовая стратегия |
| `comms-strategy.md` | этап 06 | коммуникационная стратегия |
| `validation-plan.md` | этап 07 | план проверки |
| `decisions.md` | после решения | журнал решений и условия пересмотра |
| `summary.md` | этап 07 | 5–7 строк для руководителя |
| `report.md` | `build_report.py` | итоговый отчёт |
| `calc/` | `analyze.py` | воспроизводимые расчёты |

## 2. Этапы

| Код | Этап | Результат | Человек |
| --- | --- | --- | --- |
| `01-intake` | постановка | `brief.md` | отвечает на уточнения |
| `02-collect` | сбор | `sources/`, `sources.yaml`, записи evidence | — |
| `03-research` | исследование | `situation.md` | — |
| `04-options` | варианты | `options.md` | — |
| `05-decision` | выбор | `decision.md` | **выбирает вариант** |
| `06-strategy` | стратегии | `product-strategy.md`, `comms-strategy.md` | — |
| `07-validation` | план проверки | `validation-plan.md`, `report.md` | — |

После `07` работает пересмотр (`revise`): новые данные → затронутые записи и выводы.

Статусы этапа: `pending`, `in_progress`, `waiting_human`, `done`, `skipped`.

## 3. state.json

Схема: `docs/schemas/state.schema.json`. Пример: `projects/_example/state.json`.

| Поле | Тип | Смысл |
| --- | --- | --- |
| `schema_version` | число | версия формата, сейчас `1` |
| `task_id` | строка | совпадает с именем папки |
| `title` | строка | вопрос задачи одной фразой |
| `created`, `updated` | ISO-время | создание и последнее изменение |
| `stage` | код этапа | текущий этап |
| `stages` | объект | статус каждого из 7 этапов |
| `steps` | массив | все шаги по порядку (см. ниже) |
| `waiting_for_human` | объект или `null` | вопрос, на котором агент остановился |
| `open_questions` | массив | что ещё нужно выяснить и почему это важно |

Шаг (`steps[]`):

| Поле | Смысл |
| --- | --- |
| `id` | порядковый номер, не меняется |
| `stage` | код этапа |
| `action` | что делаем, одной фразой |
| `status` | `in_progress`, `done`, `failed`, `skipped` |
| `started`, `finished` | ISO-время |
| `outputs` | какие файлы создал или изменил |
| `model` | какая модель выполняла (для маршрутизации и стоимости) |
| `error` | текст ошибки при `failed`, иначе `null` |

**Правило продолжения.** Новая сессия начинается с `python scripts/state.py status`.
Шаги со статусом `done` не повторяются. Шаг `in_progress` или `failed` —
продолжаем с него. Если `waiting_for_human` не `null` — сначала задаём этот вопрос.

## 4. evidence.jsonl — реестр утверждений

Одна JSON-запись на строку. Схема: `docs/schemas/evidence.schema.json`.

| Поле | Обяз. | Смысл |
| --- | --- | --- |
| `id` | да | `E001`, `E002`, … — не переиспользуются, даже после отзыва |
| `claim` | да | утверждение одной фразой, с единицами и периодом |
| `type` | да | `fact`, `hypothesis`, `forecast`, `synthetic` |
| `source` | для fact и synthetic | id источника `S…` |
| `where` | для fact | где в источнике: страница, раздел, строка таблицы |
| `basis` | для hypothesis и forecast | на чём основано: id других записей и/или рассуждение |
| `confidence` | да | `high`, `medium`, `low` |
| `status` | да | `active` или `revoked` |
| `revoked_by` | при revoked | что опровергло: id записи или источника |
| `revoked_reason` | при revoked | почему отозвано |
| `topics` | да | 1–3 метки темы латиницей: `retention`, `pricing`, … |
| `stage` | да | на каком этапе добавлено |
| `added` | да | дата `YYYY-MM-DD` |

**Типы:**
- `fact` — проверяемо по источнику; без `source` и `where` не допускается.
- `hypothesis` — наше предположение; обязательно `basis`.
- `forecast` — оценка будущего; обязательно `basis`, в тексте всегда помечается как прогноз.
- `synthetic` — ответ модельного респондента. Годится только для поиска гипотез,
  **никогда** не подтверждает спрос или распространённость потребности.

**Отзыв.** Записи не удаляются и не переписываются. Устаревшая запись получает
`status: revoked`, `revoked_by` и `revoked_reason`; при необходимости
добавляется новая запись с новым id.

## 5. sources.yaml — реестр источников

Список записей. Пример: `projects/_example/sources.yaml`.

| Поле | Обяз. | Смысл |
| --- | --- | --- |
| `id` | да | `S001`, `S002`, … |
| `kind` | да | `site`, `pdf`, `docx`, `xlsx`, `csv`, `interview`, `synthetic`, `user_file` |
| `title` | да | название |
| `url` | для site | адрес страницы |
| `original_file` | для файлов | имя исходного файла от пользователя |
| `local` | да | путь к копии внутри папки задачи: `sources/S001.md` |
| `publisher` | желательно | кто опубликовал |
| `published` | если известно | дата публикации |
| `retrieved` | да | дата загрузки |
| `sha256` | да | хэш локальной копии (переводы строк приводятся к LF) — чтобы видеть, что файл не менялся |
| `original_sha256` | для файлов | хэш исходного файла пользователя — чтобы не добавить его дважды |
| `status` | да | `ok` или `unavailable` |
| `notes` | нет | ограничения источника: выборка, период, методика |

Повторная загрузка того же `url` не создаёт новую запись.

## 6. Метки в текстах

| Метка | Где | Смысл |
| --- | --- | --- |
| `[E012]` | любой `.md` с результатами | утверждение опирается на запись E012 |
| `[E012][E015]` | там же | несколько опор — метки подряд |
| `[P3]` | `comms-strategy.md` | обещание опирается на пункт 3 продуктовой стратегии |

В `product-strategy.md` пункты, на которые может ссылаться коммуникация,
нумеруются как `**P1.**`, `**P2.**`, …

Регулярные выражения для скриптов: `\[(E\d{3,})\]` и `\[(P\d+)\]`.

**Правило:** любое предложение с числом, процентом, датой или фактом о рынке,
пользователях и конкурентах несёт хотя бы одну метку `[E…]`.

## 7. log.md

Одна строка на событие, новые снизу:

```
2026-11-14 18:20 | step 14 | 03-research | done | сопоставил S003 и S007 → situation.md
2026-11-14 18:31 | step 15 | 03-research | failed | S009 недоступен (timeout)
```

## 8. cost.csv

```
timestamp,step_id,stage,model,input_tokens,output_tokens,usd,estimated
2026-11-14T18:20:00,14,03-research,strong-model,18200,2100,0.09,false
```

`estimated = true`, если среда не отдала токены и расход оценён по длине текста.
Цены моделей — `config/models.yaml`. В Claude Code строки добавляет хук
`scripts/hooks/claude_cost_hook.py` (событие Stop, `.claude/settings.json`).
