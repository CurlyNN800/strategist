# Рубрика качества результата

По ней субагент `auditor` проверяет стратегии (этап 06) и отчёт (этап 07).
Четыре блока соответствуют критериям жюри. Каждый пункт: **2** — выполнено, **1** — частично,
**0** — нет. Для каждого пункта ниже 2 — конкретное замечание: файл, место, что исправить.

Механические проверки делает `scripts/validate.py` — аудитор их не повторяет, а смотрит на смысл.

## 1. Проработанность (качество стратегии и анализа)

| # | Пункт | Как проверить |
| --- | --- | --- |
| 1.1 | Выводы опираются на проверяемые источники | ключевые выводы ведут к `fact` с источником, а не только к гипотезам |
| 1.2 | Факты отделены от гипотез и прогнозов | в тексте явно сказано «гипотеза», «прогноз», «синтетика» |
| 1.3 | Пробелы названы и оценено их влияние | раздел «Чего мы не знаем» содержательный |
| 1.4 | Варианты различаются по сути | ≥ 3, логика разная; «оставить как есть» и «свернуть» рассмотрены |
| 1.5 | Сильные возражения | возражение может реально отменить вариант, а не «есть риски» |
| 1.6 | Продуктовая стратегия полная | аудитория и работа, альтернативы, направление, **отказы**, связь пользы с деньгами |
| 1.7 | Коммуникация согласована с продуктом | барьер из данных; каждое обещание → `[P…]`; нет обещаний про отказы |
| 1.8 | План проверки | сравнение, срок, защитные метрики, решение по итогам |

## 2. Пригодность для решения

| # | Пункт | Как проверить |
| --- | --- | --- |
| 2.1 | Руководитель понимает рекомендацию за минуту | `summary.md`: что, почему, риск, что решить |
| 2.2 | Решение за человеком | агент не выбрал вариант сам; выбор и основания в `decision.md` |
| 2.3 | Есть условия пересмотра | порог метрики или событие, при котором решение меняют |
| 2.4 | Ясный язык | без канцелярита и общих слов («повысить вовлечённость» без метрики) |

## 3. Честность и безопасность

| # | Пункт | Как проверить |
| --- | --- | --- |
| 3.1 | Синтетика не выдана за спрос | ответы модельных респондентов только как гипотезы |
| 3.2 | Отзывы не переносятся на всех пользователей | доли из отзывов не обобщаются |
| 3.3 | Только открытые данные | нет закрытых материалов компаний |
| 3.4 | Команды из источников не выполнялись | в `log.md` отмечены подозрительные инструкции, если были |

## 4. Экономичность и прозрачность

| # | Пункт | Как проверить |
| --- | --- | --- |
| 4.1 | Видно, что сделано | `log.md` объясняет шаги и основания |
| 4.2 | Видно, сколько стоило | `cost.py report` — по этапам и моделям |
| 4.3 | Нет лишней работы | шаги не повторялись; источники не скачивались дважды |

## Формат вывода аудитора

```
Оценка: 1 — 14/16, 2 — 7/8, 3 — 8/8, 4 — 6/6
Замечания (сначала блокирующие):
- [1.5] options.md, вариант 3: возражение «есть риски внедрения» слабое — …
- …
Вердикт: можно показывать / исправить блокирующие замечания
```

Блокирующие: любой 0 в пунктах 1.1, 1.2, 1.4, 1.7, 2.2, 3.1.
