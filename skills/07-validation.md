# 07-validation — план проверки и итоговый отчёт

**Цель:** понять, как узнать, что стратегия сработала, и собрать итог для руководителя.

**Вход:** `decision.md`, `product-strategy.md`, `comms-strategy.md`, `evidence.jsonl`.

## Шаги

1. Для каждого ключевого ожидания из стратегий заполни в `validation-plan.md`:
   - **ожидаемое изменение** — метрика, направление, величина (как `forecast`);
   - **с чем сравниваем** — контрольная группа, период до, когорта;
   - **срок наблюдения** — когда смотрим и почему именно тогда;
   - **нежелательные последствия** — что может ухудшиться и какой порог остановит эксперимент.
2. Запиши решение и обязательства в реестр решений (журнал `decisions.md` соберётся сам):
   ```
   python scripts/decision.py add <task> --title "<решение>" --option <№> --grounds E…,E…           --owner "<роль, не имя>" --metric "<метрика из плана>" --review-if "<условие>" --review-by <дата>
   python scripts/decision.py commit <task> D1 --what "<что сделать>" --owner "<роль>" --due <дата> --ref P…
   ```
   Обязательства — ключевые шаги из `product-strategy.md` и `validation-plan.md` (запуск, замер,
   точка решения). Ответственных и сроки предложи, но подтверди у пользователя.
   `python scripts/decision.py check <task>` — покажи пользователю, что из этого решать сейчас.
3. Напиши `summary.md` — 5–7 строк для руководителя: что рекомендуем, почему (с метками `[E…]`),
   главный риск, чего не знаем, что решить сейчас.
4. `python scripts/build_report.py <task>` → `report.md`: скрипт соберёт все разделы, раскроет
   метки в приложении «Утверждения» и добавит источники и стоимость.
5. `python scripts/validate.py <task>` — перед показом отчёта.

## Выход

`validation-plan.md`, `decisions.md`, `summary.md`, `report.md`.

## Проверка перед завершением

- [ ] У каждого ожидания есть сравнение, срок и нежелательные последствия.
- [ ] `report.md` читается без остальных файлов.
- [ ] Валидатор без ошибок. `python scripts/state.py stage <task> 07-validation done`.
- [ ] Скажи пользователю: работа завершена; при новых данных — «новые данные …»;
      что решать дальше — «что решать?» (`decision.py check`).
