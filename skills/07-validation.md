# 07-validation — план проверки и итоговый отчёт

**Цель:** понять, как узнать, что стратегия сработала, и собрать итог для руководителя.

**Вход:** `decision.md`, `product-strategy.md`, `comms-strategy.md`, `evidence.jsonl`.

## Шаги

1. Для каждого ключевого ожидания из стратегий заполни в `validation-plan.md`:
   - **ожидаемое изменение** — метрика, направление, величина (как `forecast`);
   - **с чем сравниваем** — контрольная группа, период до, когорта;
   - **срок наблюдения** — когда смотрим и почему именно тогда;
   - **нежелательные последствия** — что может ухудшиться и какой порог остановит эксперимент.
2. Добавь условия пересмотра решения из `decision.md` в журнал `decisions.md`:
   решение, основания `[E…]`, ответственный, метрика, условие пересмотра.
3. `python scripts/build_report.py <task>` → `report.md`
   (пока скрипта нет — собери вручную: краткий вывод, ситуация, варианты, решение,
   стратегии, план проверки, список источников).
4. В начале `report.md` — 5–7 строк для руководителя: что рекомендуем, почему, чего не знаем.
5. `python scripts/validate.py <task>`, затем `python scripts/cost.py report`
   и добавь в конец отчёта, сколько стоила работа.

## Выход

`validation-plan.md`, `decisions.md`, `report.md`.

## Проверка перед завершением

- [ ] У каждого ожидания есть сравнение, срок и нежелательные последствия.
- [ ] `report.md` читается без остальных файлов.
- [ ] Валидатор без ошибок. Этап `07-validation` → `done`.
- [ ] Скажи пользователю: работа завершена; при новых данных — «новые данные …».
